## PR 5.1b — تغيير البريد الإلكتروني + خطوة الإيميل بالتوثيق — 2026-10-14

- تغيير الإيميل بالإعدادات (كان «قريباً»): الإيميل الجديد + كلمة السر الحالية → `POST /auth/email-change/request` → رابط تأكيد للإيميل الجديد (`/confirm-email#token=…`) · الإيميل ما بيتغيّر إلا بعد كبسة الرابط (`POST /auth/email-change/confirm`) · بعدها تنبيه «تغيّر بريدك الإلكتروني» للعنوان القديم (بدون رابط إلغاء بهالمرحلة).
- التوكن نفس كود «نسيت كلمة المرور»: `auth.email_token_issue` / `email_token_consume` بعمود `purpose` + `payload` جديدين بجدول `password_reset_tokens` (hash بس · 30 دقيقة · مرة وحدة · الجديد بيلغي القديم · توكن ما بيعبر بين الأغراض).
- إيميل مستعمل لحساب تاني → 422 `email_taken` بالطلب و 409 بالتأكيد (سباق) — عبر `EmailTakenError` · حد 5 طلبات / ساعة لكل مستخدم + حد الـ IP.
- خطوة الإيميل بالتوثيق شغّالة: `is_email_otp_delivery_available()` = الإيميل configured + النوع مفعّل · الرمز بينبعت عبر `send_email` (قالب `kyc_email_otp`) لبريد الحساب بس · الهاتف لسا بدون مزوّد SMS → `verify_identity` بيضل مطفّى.
- قوالب جديدة `email.email_change.*` / `email.email_changed.*` / `email.kyc_email_otp.*` + أنواع بإعدادات الإيميل بالأدمن (تشغيل / إيقاف).
- صفحة جديدة `/confirm-email` · اختبار `tests/test_email_change_kyc_email.py` · فحص J2 بـ `test_privacy_boundary.py` صار سلوكي.
