## PR 6.3 — مجدول موثوق: مشغّل داخلي كل 60 ث + قفل + نبض + وظائف عالقة + إعادة إرسال الإيميل — 2026-10-22
- السبب الجذري: GitHub cron كان المشغّل الوحيد وبيتأخر ساعات → إيميلات الرسائل والتذكيرات بتتأخر (AUD-P1-05 · AUD-P2-22).
- `server._scheduler_loop` (asyncio) بيشغّل `auth.run_scheduler_cycle()` كل 60 ثانية — بيبلّش بالـ startup وبيوقف بالـ shutdown، فشل دورة بينكتب بالـ log بس. `SCHEDULER_LOOP=0` بيطفّيه.
- `run_scheduler_cycle` = المدخل الوحيد (الـ loop + `POST /internal/run-due-jobs`) تحت `pg_try_advisory_lock` — worker / instance تاني بيرجع `skipped: locked` وما بيشغّل شي.
- نبض `site_settings[scheduler_last_ok]` → `/health` `scheduler: ok | stale` (أقدم من 10 دقايق).
- وظائف `running` أقدم من 15 دقيقة بترجع `pending` (أو `failed` إذا خلصت المحاولات) (AUD-P2-31) · إعادة المحاولة بعد `attempts × 5` دقايق (حد 60).
- إيميل رسالة فشل إرساله ما بينعلّم «تم» — بيرجع للمحاولة بنفس العداد (AUD-P2-43).
- `scheduler-cron.yml` احتياط: `ok:false` أو وظائف فاشلة → الـ run أحمر (AUD-P2-23).
