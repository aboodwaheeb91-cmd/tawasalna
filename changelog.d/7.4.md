## PR 7.4 — رابط متابعة الزائر بيحدد التذكرة بس، والمحادثة بعد رمز تحقق على إيميل صاحبها — 2026-10-26

- الرابط `/support/track#t=…` ما عاد تفويض: `POST /support/track/view {token}` بيرجّع رقم H + الإيميل مقنّع (`a***@…`) + `verified:false` بس — بدون الرسائل ولا الموضوع ولا الحالة. تحويل الإيميل ما بيعطي حدا قراءة المحادثة أو الرد.
- جديد `POST /support/track/code {token}` (بطلب صريح، نفس الرد دايماً): رمز OTP لـ `guest_email` المخزّن بالتذكرة بس (`guest_otp_issue` + `support_guest_otp`) · نفس حدود الـ OTP + cooldown جديد `support_track_code_ticket` (1 / 60 ث لكل تذكرة، `tw_limits`).
- جديد `POST /support/track/verify {token, code}` → جلسة 24 ساعة ثابتة بجدول جديد `support_guest_sessions` (hash بس) · رمز غلط → 422 بنص عام.
- `view` (المحتوى) + `reply` + `resolve` بيقبلوا `{session}` بس، محصورة بتذكرتها · منتهية / ملغاة / غلط / رمز الرابط → 401 واحد.
- أي رابط جديد (إعادة الإرسال · رد الأدمن) بيلغي جلسات التذكرة · انشال تمديد صلاحية الرابط عند الرد.
- صفحة `/support/track`: الرمز بـ `sessionStorage` (مفتاح واحد) · شاشة «سنرسل رمز تحقق إلى a***@…» + «أرسل الرمز» + خانة الرمز · بدون رابط ولا جلسة → «افتح رابط المتابعة من الإيميل» · 401 → شاشة الرمز · التحديث بيحافظ على الجلسة.
- نص ملاحظة إيميل `support_guest_link` اتعدّل (ما عاد «أي شخص معه الرابط بيقدر يشوف طلبك»).
- الإنتاج: كود الإقلاع بينشئ الجدول الجديد بس (`CREATE TABLE IF NOT EXISTS`) — `rls_lockdown` بيغطيه.
