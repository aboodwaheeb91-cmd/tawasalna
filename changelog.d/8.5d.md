## PR 8.5d — حذف الحساب من صاحبه + «استعادة حسابي» + إيميلات التأكيد + المحادثة مع حساب محذوف — 2026-10-31

- `DELETE /auth/user/{id}/delete` انفتح: حذف ناعم `kind='self'` عبر `ad.soft_delete` بكلمة السر + `confirm: "delete"` · حساب تاني 403 · بدون كلمة سر / تأكيد 422 بدون حجز · حجز `account_delete` قبل bcrypt (429) · كلمة سر غلط 422 مش 401 · نفس `apply_effects` (وظائف بتتسكّر · مقابلات بتنلغى) + إيميل أمان `account_deleted` مرة وحدة (موعد نهاية المهلة، بدون رابط).
- `POST /auth/restore` جديد (بدون JWT): نفس أقفال الدخول + `account_restore` قبل bcrypt · إيميل / كلمة سر غلط = رد الدخول 401 حرفياً (bcrypt وهمي للإيميل المش موجود — نفس التوقيت) · `ad.restore(self_only=True)` بيفحص جوّا القفل: `not_deleted` 409 · حذف أدمن 403 · `purging` / `already_purged` 409 · `expired` 409 · نجاح → توكن جديد + إيميل `account_restored`.
- الدخول لحساب محذوف بكلمة سر صح → `restorable` + `restore_until` · صفحة الدخول: زر «استعادة حسابي» → `twConfirm` → طلب منفصل → نفس مسار نجاح الدخول.
- `/settings` «منطقة الخطر»: شلنا «قريباً» — نافذة بتحذير المهلة (`twLimit('account_purge_days')`) + كلمة السر + «اكتب حذف» (الزر معطّل لحد ما تطابق) → خروج عبر `TwAuthSync` → `/login?account=deleted`.
- المراسلة: محاور محذوف مع رسائل سابقة → `peer_deleted` «لا يمكن الرد على هذا الحساب» (المحادثة قراءة بس — بدون composer / إنهاء / موعد / رابط ملف) · بدون رسائل سابقة → `not_found` متل قبل. الإرسال لمحذوف مع تاريخ صار 403 `peer_deleted` بدل 404.
- `RATES["account_delete"]` / `["account_restore"]` بـ `tw_limits.py` · `account_purge_days` بـ `window.TW_LIMITS`.
- تصحيح: استعادة حساب معلّق بتبعت إيميل `account_restored` (الرد بيضل 401 `account_suspended` بدون توكن) · صفحة الدخول بتعرض نص كل كود خطأ استعادة لحاله بدل نص `expired` لكل 409.
