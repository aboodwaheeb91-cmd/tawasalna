## PR 5.0g — سياسة المحادثات بالسيرفر (AUD-P1-01) — 2026-10-20

- أمني / سلوك: قاعدة وحدة `auth.can_send_message(sender, receiver)` — النوع والتاريخ والمتابعة والإنهاء من القاعدة (مش من التوكن). محادثة موجودة (رسالة سابقة بأي اتجاه) بتضل مفتوحة للطرفين حتى بعد إلغاء المتابعة (ومنها كل المحادثات الحالية). جديدة: شركة / جهة تعليمية → أي حدا · شخصي → جهة تعليمية · شخصي ↔ شخصي بمتابعة متبادلة بس · شخصي → شركة ممنوع (403 «لا يمكنك بدء محادثة مع شركة»).
- `POST /messages/send` (asyncpg + pg8000) بيفحص القاعدة بنفس transaction الإدراج بعد قفل `pg_advisory_xact_lock` على الزوج (نفس القفل بالإنهاء) — إرسالين أو إرسال + إنهاء بنفس اللحظة ما بيتجاوزوا الفحص. الرفض → `{ok:false, error:{code, message}}` بنص twT `msg.policy.*`.
- جديد: جدول `conversation_endings` (migration حرجة `conversation_endings`) + `POST /messages/conversations/{id}/end` — الشركة بتنهي محادثتها مع حساب شخصي (بدون إشعار). الشخص بيشوف الرسائل القديمة بس الإرسال 403 «أنهت الشركة هذه المحادثة»؛ أول رسالة من الشركة بتفتحها من جديد.
- جديد: `GET /messages/can-send/{id}` → `{can_message, reason, reason_key, ended, can_end}` + `twCanMessage(id)` بـ `tw_shared.js`. السجل: حقل `visibleWhen` (`can_message` / `can_end`) — زر «مراسلة» بصفحات الملف الشخصي / الشركة / الجهة التعليمية بيطلع بس إذا مسموح · إجراء جديد `end_conversation` (danger + تأكيد) بهيدر المحادثة للشركة. `GET /profile/{id}` → `permissions.can_message` صار من نفس الدالة (كان دايماً `true`).
- `messages.html`: مكان الكتابة بيستنى قرار السيرفر؛ مرفوض → السبب مكانه (`#chatLocked`) · فشل إرسال بـ 403 → بيعيد قراءة القرار.
- اختبار: `python -m pytest tests/test_conversation_policy.py -q` (11 حالة — كل حالات القرار + الإنهاء + طرف تالت + القفل + مسار asyncpg). فحوص stubs محدّثة: `test_actions_registry_runtime.js` (C2b/C2c) · `test_company_profile_page_runtime.js` (D4b) · `test_settings_edu_runtime.js` (G5b/G5c).
