## Email Rules (mandatory for all AI sessions)

1. **مرسل واحد:** `email_service.send_email(to, template_key, vars)` هي الدالة الوحيدة اللي بتبعت إيميل بالموقع (Resend HTTP API — Railway بيسكّر SMTP). ما بترمي أبداً؛ بترجّع `{ok, code}` — `sent` · `unavailable` (مفتاح غايب) · `disabled` (النوع مطفّى) · `invalid` · `failed`.
2. **المفتاح:** `RESEND_API_KEY` من البيئة بس. ممنوع يطلع بأي log أو رد أو صفحة. `/health` → `email: configured | missing` · `GET /admin/email` → `status` بس.
3. **التحكم الكامل:** `site_settings[email_settings]` = `from_address` (افتراضي `no-reply@tawasolna.com`) · `from_name` («تواصلنا») · `site_url` (أصل روابط الإيميل — **مش** من `Host` header: reset-link poisoning) · `types` (تشغيل / إيقاف كل نوع). الأدمن: `GET` / `PUT /admin/email` + `POST /admin/email/test` (`check_admin`).
4. **القوالب:** نوع جديد = سطر بـ `TEMPLATES` (`email_service.py`) + مفاتيح `email.<type>.<part>` بـ `tw_strings.json` (قابلة للتعديل من الأدمن عبر `PUT /admin/strings`) + بـ `TYPES` إذا الأدمن لازم يقدر يطفّيه. قالب HTML واحد RTL (ألوان من primitives `tw_shared.css`) + نسخة نص عادي. كل متغيّر مُهرَّب بالـ HTML؛ العنوان بدون أسطر جديدة؛ زر الرابط بس لـ `https://`.
5. **الـ logs:** النوع + السبب بس (`http 500` / نوع الخطأ) — ❌ المفتاح · ❌ عنوان المستلم · ❌ النص · ❌ رابط / توكن.
- ❌ `smtplib` / مزوّد تاني / `urlopen` لـ Resend برّا `email_service.py` · ❌ نص إيميل ثابت بالكود · ❌ رابط إيميل مبني من `request`.
6. **OTP التوثيق (5.1b):** `is_email_otp_delivery_available()` = `email_service.can_send("kyc_email_otp")` · الرمز بينبعت عبر `send_email` (قالب `kyc_email_otp`) لبريد الحساب (`users.email`) بس — عنوان تاني بالطلب → 400 · الرمز مخزّن hash (`_otp_issue`) متل ما هو. الهاتف بدون مزوّد SMS → `verify_identity` بيضل مطفّى افتراضياً.

## Forgot Password Rules (mandatory for all AI sessions)

1. **طلب الرابط** `POST /auth/password-reset/request {email}` → **نفس الرد دايماً** `{ok:true, data:{sent:true}}` لإيميل موجود وغير موجود؛ البحث + التوكن + الإيميل بـ `BackgroundTasks` بعد الرد (ما في فرق وقت). حدود على `_rate_store` المشترك: لكل IP (`get_client_ip`) 10 / ساعة → 429 · لكل إيميل 3 / ساعة → نفس الرد بدون إرسال. خدمة الإيميل غير متاحة / النوع مطفّى → 503 `email_unavailable` (عام — ما بيكشف شي).
2. **التوكن** (`auth.py`): `secrets.token_urlsafe(32)` · مخزّن HMAC بس (`v1$` — متل الـ OTP) بجدول `password_reset_tokens` · 30 دقيقة (ساعة الـ DB) · استعمال مرة (`DELETE … RETURNING`) · توكن جديد بيحذف كل الأقدم لنفس المستخدم.
3. **الرابط** `{site_url}/reset-password#token=…` — بالـ fragment (ما بيوصل للسيرفر / الـ logs / Referer)؛ الصفحة بتشيله من شريط العنوان فوراً.
4. **التعيين** `POST /auth/password-reset/confirm {token, new_password}` → `_password_policy_error` (نفس قاعدة التسجيل) → `set_user_password` (بيكتب `password_changed_at` + بيزيد `session_version` + بيحذف كل توكنات الإيميل تبع المستخدم — 5.0b) → `_password_changed_cache_set` + `_ws_revoke_user(uid, "password_reset")` (كل الجلسات القديمة بتطلع) + فك قفل الدخول للإيميل (`login_email` + `login_ip_email` لهالإيميل من **أي IP** — `_login_email_reset(email, every_ip=True)`، task 7.5b؛ قفل الـ IP لحاله `login_ip` بيضل) + إيميل «تغيّرت كلمة مرورك». ما في دخول تلقائي.
- ❌ رد بيختلف حسب وجود الإيميل · ❌ التوكن نص عادي بالـ DB أو بالـ log · ❌ التوكن بـ query string · ❌ كتابة `password_hash` بدون `set_user_password` · ❌ مسار بينهي جلسات بدون `_ws_revoke_user`.

Test: `python -m pytest tests/test_password_reset_email.py -q` (Resend مزيّف على مستوى HTTP + PostgreSQL حقيقي).

## Email Change Rules (mandatory for all AI sessions — task 5.1b)

1. **الطلب** `POST /auth/email-change/request {new_email, current_password}` (JWT) → كلمة السر الحالية (bcrypt) · صيغة الإيميل · نفس الإيميل الحالي · مستعمل لحساب تاني → 422 `new_email/email_taken` عبر `EmailTakenError` (مش نص الخطأ) · 5 / ساعة لكل مستخدم (قبل فحص كلمة السر) + `_RATE_LIMITED_PATHS`.
2. **التوكن = نفس كود نسيت كلمة المرور:** `auth.email_token_issue` / `email_token_consume` (purpose `email_change`، الإيميل الجديد بـ `payload`) — hash بس · 30 دقيقة · مرة وحدة · الجديد بيلغي القديم. ❌ جدول أو دالة توكن تانية.
2b. **تغيير كلمة السر بيلغي كل الروابط المعلّقة (5.0b):** `set_user_password` بيحذف كل صفوف المستخدم بـ `password_reset_tokens` (كل الأغراض) بنفس الـ statement — رابط `email_change` صادر قبل تغيير / استعادة / تعيين أدمن لكلمة السر → confirm = 400 `invalid_token` والإيميل ما بيتغيّر. ❌ غرض توكن جديد بجدول تاني (بيفلت من الحذف). Test: `python -m pytest tests/test_session_version_tokens.py -q`.
3. **الرابط** `{site_url}/confirm-email#token=…` للإيميل **الجديد** · الصفحة بتبعت التوكن بس بكبسة زر (مش عند التحميل — ماسحات الروابط).
4. **التأكيد** `POST /auth/email-change/confirm {token}` → وقتها بس `users.email` بيتغيّر · مستعمل بالوقت (سباق) → 409 `email_taken` عبر `EmailTakenError` (UNIQUE) · بعدها إيميل «تغيّر بريدك الإلكتروني» (`email_changed`) للعنوان **القديم** — بدون رابط إلغاء بهالمرحلة.
- ❌ تغيير `users.email` قبل الرابط · ❌ إرسال برّا `send_email`.

Test: `python -m pytest tests/test_email_change_kyc_email.py -q`.

## Notification Emails Rules (mandatory for all AI sessions — task 5.1c)

1. **التصنيف:** كل قالب بـ `TEMPLATES` إلو `category`: `security` (`password_reset` · `password_changed` · `email_change` · `email_changed` · `kyc_email_otp` · `support_guest_otp` · `support_guest_link` · `support_guest_reply` · `support_reply` · `admin_test`) أو `notification` (`notify_*`). الأمان **ما بيتأثر** لا بالحد ولا بتفضيلات المستخدم (مفتاح الأدمن تبع 5.1a بيضل متل ما هو). قالب جديد بدون `category` = غلط.
2. **بوابة واحدة جوّا `send_email`:** إيميل `notification` لازم `user_id` (+ `ref_key` اختياري) → `auth.email_notify_reserve` (مسجّلة من `server.py` عبر `email_service.set_send_hooks`) بـ transaction وحدة تحت `pg_advisory_xact_lock`: تفضيل المستخدم → `skipped_pref` · throttle الرسائل (`notify_message` + نفس `ref_key` خلال `message_throttle_hours`) → `skipped_throttle` · الحد اليومي / الشهري (صفوف `notification` بحالة `sent` / `sending` من بداية اليوم / الشهر UTC) → `skipped_cap` · غير هيك صف `sending` بيصير `sent` / `failed`. مفتاح الأدمن مطفّى → `disabled` (صف `skipped_off`). البوابة مش مسجّلة → `unavailable` (fail-closed). ❌ إرسال إيميل إشعار بدون `user_id` · ❌ عدّ الحد من مكان تاني.
3. **العداد = `email_send_log`** (`created_at` · `template_key` · `category` · `status` · `user_id` · `ref_key`) — كل محاولة صف واحد (أمان + إشعار) عبر hook الـ log؛ فشل الكتابة بالـ log بيتسجّل وما بيوقّف الإرسال. migration `_migrate_email_notify` (critical).
4. **نقاط الربط (بس هدول):** `create_notification` → `_notification_email` لأنواع `NOTIFICATION_EMAIL_TEMPLATES` (`appointment_invited` / `appointment_rescheduled` / `appointment_cancelled`) — الإيميل على thread pool (`_email_submit`) بعد إنشاء الإشعار، فالإشعار داخل الموقع ما بيتأثر بأي منع. الرسائل: `POST /messages/send` (cold path بس — المستلم مش فاتح المحادثة) → `schedule_message_email` → scheduler job `message_email` بعد `message_delay_minutes` (dedupe لكل مستلم + مرسل بكل نافذة) → `_handle_message_email` بيبعت بس إذا الرسالة لسا `is_read = FALSE` — بدون نص الرسالة بالإيميل. إرسال رجع `failed` / `unavailable` → الـ job بيرجع `pending` (بعد `attempts × 5` د) بنفس عداد المحاولات، مش `done` (task 6.3 — AUD-P2-43). نتيجة طلب التوظيف (5.1d): `notify_application_result` → `create_notification` (البند 5). رسالة الأدمن (5.3b2): `POST /admin/message` → `create_notification(type admin_message)` → قالب `admin_message` (notification، `{title}` = العنوان، `{details}` = نص الأدمن بعد escape) + مفتاح تفضيل للمستخدم `admin_message` («رسائل الإدارة»). ❌ hook تاني بصفحة أو endpoint.
5. **نتيجة طلب التوظيف (task 5.1d — قرار سياسة، بيلغي «السبع داخلية» تبع PR #479):** المراحل الوسطية (`pending` / `viewed` / `accepted` / `contacted` / `interview`) داخلية — ❌ أي إشعار أو إيميل للمتقدم عنها. `hired` / `rejected` بس → `auth.notify_application_result(app_id, stage)` بعد commit تبع `update_application_status` و `update_candidate_job_status` (نقطة الربط الوحيدة) → إشعار (`application_hired` / `application_rejected`) عبر `create_notification` → إيميل (`notify_application_hired` / `notify_application_rejected`) من نفس البوابة. **مرة وحدة لكل طلب ولكل حالة نهائية** (`event_key = application_result:job_application:{app_id}:{stage}`). الرفض: نص عام لطيف — ❌ سبب · ❌ اسم مرحلة · ❌ اسم الشخص؛ القبول: اسم الوظيفة + الشركة بس. المفاتيح: أدمن `types.notify_application_{hired|rejected}` (مطفّى → لا إشعار ولا إيميل لهالحالة) · الشركة `company_settings.notify_applicant_result` (SYSTEMS_INDEX §20e، مطفّى → ولا شي) · المستخدم `notify_application_result` (إيميل بس).
6. **تحكم الأدمن:** `site_settings[email_settings]` → `types.notify_*` (تشغيل / إيقاف) + `notify` = `email.notify.daily_cap` (80) · `monthly_cap` (2800) · `message_delay_minutes` (15) · `message_throttle_hours` (6) — أرقام صحيحة بحدود `NOTIFY_LIMITS` (غير هيك 422). الصفحة `/tw-ctrl-{ADMIN_URL_TOKEN}/email` (`admin-email.html` + `static/admin-email/admin-email.js`, `TwAdminSession`): حالة المزوّد · الاستهلاك (اليوم / الشهر × أمان / إشعارات + «انمنع بسبب الحد») · الأنواع · الحدود · قواعد الرسائل — كل كرت إلو ⓘ. إطفاء نوع أو خفض حد للنص أو أقل → `twConfirm` قبل الحفظ.
7. **تفضيلات المستخدم:** `GET` / `PUT /my/email-notifications` (JWT، `{types:{<مفتاح>: bool}}` — المفاتيح = `email_service.PREF_TYPES`؛ مفتاح واحد ممكن يغطّي أكتر من نوع عبر `PREF_GROUPS` (5.1d: `notify_application_result` = hired + rejected) والبوابة بتفحص `pref_key(template)` — نوع أمان أو نوع مش مفتاح → 422) · جدول `email_notify_prefs (user_id, type, enabled)` (صف بس لما يتغيّر؛ غيابه = مفعّل). `settings.html` قسم `#notifications`: مفتاح لكل نوع (حفظ فوري، رجوع عند الفشل، نوع مطفّى من الأدمن = معطّل) + سطر إن إيميلات الأمان دايماً بتوصل.
8. **آخر كل إيميل إشعار:** رابط `{site_url}/settings#notifications` (نص + HTML) + هيدر `List-Unsubscribe: <{site_url}/settings#notifications>`. إيميلات الأمان بدونهم.

9. **إشعار رد الدعم (task 7.2b — `docs/rules/support.md` → إشعارات الرد):** قالبين **SECURITY**: `support_guest_reply` (`ticket` · `link` — «يوجد رد جديد على طلبك H…» + زر رابط المتابعة + «لا تشارك هذا الرابط») و `support_reply` (`name` · `ticket` · `link` = `/support?ticket=H…` absolute على `site_url`). **ليش SECURITY:** هاد جواب على طلب صاحبه فتحه بنفسه (متل رابط إعادة التعيين) — إذا ضاع بالحد اليومي أو بتفضيل مطفي، صاحب الطلب ما بيعرف إنه في رد وطلبه بيعلق؛ والإيميل ما فيه نص الرد (رقم H بس)، فما في محتوى بيتسرّب. الأدمن بيقدر يطفّي كل نوع (`types`). نوع الإشعار `support_reply` **مش** بـ `NOTIFICATION_EMAIL_TEMPLATES` → ما بيطلع إيميلين.

10. **البريد الوارد + Reply-To (task 7.3 — `docs/rules/support.md` → البريد الوارد):** `send_email(..., reply_to=)` اختياري — مسموح لـ `REPLY_TO_TEMPLATES` بس (`support_reply` · `support_guest_reply` · `support_guest_link`)، غيرها أو عنوان غلط → `invalid` بدون إرسال. Resend بمكان واحد: `verify_webhook` (Svix، hmac، ±5 دقايق، سر `RESEND_WEBHOOK_SECRET` من البيئة بس) + `fetch_received` (`GET /emails/receiving/{id}`) بـ `email_service.py`. `types.support_inbound` = مفتاح مش قالب، **الافتراضي مطفي** (`OFF_BY_DEFAULT`). قراءة البريد الوارد بدها مفتاح Resend «Full access». **مكانه بالأدمن (7.3a):** `GET /admin/email` بيرجّع `inbound_switch` = `email_service.INBOUND_SWITCH` (الصفحة ما بتكتب الاسم ثابت) → `admin-email.js` بيرسمه ببطاقة لحالها (مش ضمن «أنواع الإشعارات»، عنوان `email.type.<key>` + تلميح `email.type.<key>.hint`، `ae-switch` + `role=switch`) — مشغّل بس إذا `settings.types[key] === true` · الحفظ بنفس `PUT /admin/email` (`types[key]`) · التشغيل بيطلب `twConfirm` بنص `admin.email.warn.inbound_on` · الإطفاء بدون تحذير و `warn.type_off` ما بينطبق عليه.
11. **تذييل إيميلات الدعم (task 7.5b):** الإيميل اللي عليه `Reply-To: support+<token>@` (يعني `send_email(..., reply_to=)` — `support_guest_link` · `support_guest_reply` · `support_reply`) تذييله `email.support.footer` («يمكنك الرد على هذه الرسالة مباشرة…») بدل `email.common.footer` («يرجى عدم الرد»). القرار بـ `render(..., reply_footer=bool(reply_to))` — فشل إصدار رمز الـ Reply-To = إيميل بدون Reply-To = التذييل العام. باقي الإيميلات (أمان، استرجاع، OTP، إشعارات) ما تغيّرت.
12. **نتيجة توثيق الهوية (task 8.1):** `kyc_approved` / `kyc_rejected` → `notify_kyc_approved` / `notify_kyc_rejected` (notification، vars `name` + `link` بس) عبر نفس البوابة — مفتاح المستخدم `notify_kyc_result` (الاتنين). ❌ سبب الرفض بالإيميل أو الإشعار — النص «افتح الإعدادات»، والسبب بيبين بـ `/settings` بس (SYSTEMS_INDEX §23).
