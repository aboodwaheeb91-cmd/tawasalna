# Admin Shell (task 5.3a · 5.3b · 5.3a3 · 5.3j)

> قوانين إلزامية بنفس قوة `CLAUDE.md` لأي مهمة بتلمس صفحة أدمن (`admin.html` · `admin-email.html` · `admin-view.html` — 5.3b).
> المواصفة: `docs/SYSTEMS_INDEX.md` §25a · جلسة الأدمن: §25 + `docs/rules/auth-identity.md → Admin Authentication`.

## Admin Shell Rules (mandatory for all AI sessions)

1. **هيدر + قائمة وحدة لكل صفحات الأدمن:** `<header data-tw-header="admin" hidden></header>` أول عنصر بالـ `<body>` + `TwAdminShell.mount()` (`static/shared/admin-shell.js`). `twMountAppChrome` بيتجاهل هالـ variant. ❌ هيدر / قائمة / تبويبات خاصة بصفحة أدمن.

2. **القائمة من registry واحد:** `TW_ADMIN_SECTIONS` بـ `static/shared/admin-sections.js` — كل قسم = `{key, icon (DS-ICON), labelKey (twT), path, badge?}`. `path` نسبي لجذر اللوحة: `''` الجذر · `'#x'` قسم من صفحة الجذر (`admin.html` بتعرض `[data-adm-section="x"]`) · `'name'` صفحة فرعية (route بـ `server.py` = جذر اللوحة + `/name`). قسم جديد = سطر بالـ registry + مفتاح نص؛ صفحة فرعية جديدة = كمان route + ملف HTML.

3. **ممنوع الـ slug أو `tw-ctrl-` بأي ملف بيوصل للمتصفح.** جذر اللوحة بينقرى وقت التشغيل من أول جزء بـ `location.pathname` (`TwAdminShell.base()`)، والدخول بيروح لـ `<جذر اللوحة>/login` (نفس `admin_login`). لصفحة برّا اللوحة (`admin-view.html`): `TwAdminShell.start({outside: true, current})` → جذر اللوحة = `TwAdminSession.panelHref()` (sessionStorage لنفس التاب). الدخول القديم الثابت `/tw-ctrl-login` انحذف (5.3b) → 404 — ❌ ترجيعه. فحص: `tests/test_page_shell_security.py` + `tests/test_admin_shell_runtime.js` (B).

4. **بوابة الجلسة — نداء واحد أول سكربت الصفحة:** `TwAdminShell.start({loginPage})` → `true` = جلسة حيّة؛ ما في جلسة → صفحة الدخول بتعرض نموذجها / أي صفحة تانية `location.replace(جذر اللوحة)`. صفحة برّا مسار اللوحة: `start({outside: true, current: '<key>'})` — تاب ما فتح اللوحة (ما في جذر محفوظ) → `false` بدون تحويل والصفحة بتعرض رسالة (`admin.view.open_panel`).

5. **انتهاء الجلسة (401 / 403 / exp) من مكان واحد:** `TwAdminShell` بيسجّل handler واحد على `TwAdminSession.onExpired` → `location.replace(جذر اللوحة + '?session=expired')` → صفحة الدخول بتعرض `admin.session.expired`. ❌ handler تاني بصفحة · ❌ فحص `r.status === 401` يدوي.

6. **كل تعديل بيانات عبر `TwAdminShell.run(action, ctx)`:** `action = {confirm?, request(ctx) → {url, method, body?}, done?, fail?}`. ما في تأكيد → ما في طلب. كل إجراء كبير (حذف، تغيير نوع حساب، تغيير كلمة سر، رفض توثيق، حل بلاغ، صيانة، استبدال الشعار) إلو `confirm` بنص بيوضّح شو رح يصير (`admin.*` بـ `tw_strings.json`). الأخطر (حذف، ترحيل/صيانة) `danger: true` + `typeWord` → نافذة `twModal` زر التأكيد فيها مطفّي لحد ما تنكتب الكلمة. ❌ `TwAdminSession.fetch` مباشر لعملية كتابة بصفحة أدمن.

7. **كل كرت / قسم إلو زر ⓘ:** `TwAdminShell.card(parent, {titleKey, hintKey, icon})` — جملة بسيطة بتشرح شو بيعمل القسم. ❌ نمط كرت-مع-ⓘ تاني.

8. **شارات الأعداد جزء من الـ shell:** `badge` بالـ registry (`reports` = بلاغات `pending` · `kyc` = طلبات `review`)؛ الصفحة بتنادي `TwAdminShell.refreshBadges()` بعد إجراء بيغيّر العدد.

9. **الصفحة نفسها:** Page Shell أدمن (`<!--tw:shell-head:admin-->` / `<!--tw:shell-scripts:admin-->`) · ترتيب السكربتات: `admin-session.js` → `tw-icons.js` → `tw-overlay.js` → `admin-sections.js` → `admin-shell.js` → سكربت الصفحة · ألوان `--color-*` بس (`admin-shell.css` + CSS الصفحة) · نص `twT` · أيقونات DS-ICON · نوافذ DS-OVL · `page_audit` = صفر.

10. **صفحة مستخدم واحد (`admin-view.html` — 5.3b):** رابطها من قائمة المستخدمين بس (مش سطر بالـ registry). كتاباتها كلها بـ `TwAdminUserView.ACTIONS` (`static/admin-view/admin-view.js`) عبر `TwAdminShell.run`: تغيير نوع الحساب = `danger` + `typeWord` «تغيير» ورسالة بتشرح شو بيتغيّر · تغيير كلمة السر = `danger` (خروج المستخدم من كل أجهزته + إلغاء روابط الإيميل المعلّقة) · حذف الحساب = `typeWord` «حذف» · حذف خبرة / شهادة / دورة · تعديل البروفايل · إلغاء التوثيق · الرسالة (`/admin/message`) = تأكيد بيشرح. نافذة بتجمع قيمة (`twModal`) زرّها بينادي `run` (التأكيد فوقها). النتيجة بتنفحص قبل «تم».

11. **الإطار (task 5.3a2):** ديسكتوب (≥ 1024px) = قائمة جانبية ثابتة يمين بلون `--color-brand-primary` + شريط علوي · موبايل = الشريط العلوي + زر القائمة → `TwAdminShell.openMenu()` = نفس روابط الـ registry جوّا `twModal` (DS-OVL — ما في drawer preset بالـ runtime) وبتسكّر لما تختار رابط. الشريط العلوي: بحث موحّد (`searchResults` — مستخدمين / شركات من `GET /admin/users?q=` بالسيرفر بعد ما يوقف الكتابة (5.3a3) + وظائف من `GET /admin/jobs`) · حالة النظام (`TwAdminShell.health()` من `/health`) · اختصارات الشارات · خروج. ❌ قائمة / بحث / مؤشر حالة تاني بصفحة أدمن.

12. **الشركات = نفس جدول المستخدمين بفلتر نوع ثابت** (`VIEWS.companies` بـ `admin.js`). ❌ كود جدول تاني لنوع حساب.

13. **لوحة القيادة = بيانات حقيقية بس (F30):** كل كرت / رسم / طابور إلو endpoint حقيقي (`GET /admin/stats/summary` · `/admin/stats/timeseries` · `/admin/activity` · `/admin/kyc` · `/admin/reports` · `/health` · `/admin/audit`). عنصر ما إلو بيانات بالموقع (إيرادات، اشتراكات، مدفوعات، إعلانات، تقييمات، دعم فني، تذاكر) → **ما بيظهر أبداً** — لا رقم وهمي ولا قسم فاضي — ومسجّل بـ `docs/FUTURE_ROADMAP.md` → Admin Panel — Missing Sections. الرسومات عبر `twChart` (`static/shared/tw-chart.js`) بس — ❌ مكتبة رسوم. metric الرسم من allowlist بالسيرفر (`TIMESERIES_METRICS`) — ❌ اسم جدول / عمود من الطلب.

14. **السجل الأمني (SYSTEMS_INDEX §25b):** كل كتابة أدمن (`POST/PUT/PATCH/DELETE` تحت `/admin/`) + كل محاولة دخول أدمن (ناجحة / فاشلة) بتتسجّل من مكان واحد: `admin_audit_middleware` بـ `server.py`. ❌ تسجيل body / كلمة سر / توكن / نص رسالة · ❌ نداء تسجيل بكل endpoint · endpoint جديد للكتابة تحت `/admin/` بيتسجّل لحاله (ما في شي تعمله).

15. **جدول المستخدمين والشركات (task 5.3a3 — SYSTEMS_INDEX §25d):** البيانات من `GET /admin/users` بس — البحث (اسم / إيميل / tw_id) والفلاتر (النوع · التوثيق: موثّق / معلّق / غير موثّق · الترتيب) والصفحات كلها بالسيرفر؛ البحث بينبعت بعد ما يوقف الكتابة. الحقول: id · tw_id · الاسم · الصورة · النوع · الإيميل · التوثيق · تاريخ التسجيل — ❌ أي حقل تاني. ديسكتوب جدول · صندوق ضيق (< 720px) صفوف مضغوطة بدون سكرول أفقي. الإجراءات: عرض · تعديل (`admin-view?id=N#edit`) · حذف (`run('user.delete')`). ❌ تحميل كل الحسابات للمتصفح · ❌ `GET /auth/users` (انحذف).

16. **التصدير CSV:** `GET /admin/users/export` بنفس الفلاتر وبنفس الأعمدة (بدون الصورة) — عبر `TwAdminShell.run(ACTIONS['users.export'])` (تأكيد قبل التحميل، `as: 'blob'`)، وبينسجّل بالسجل الأمني لأنه بـ `AUDIT_READ_ROUTES` (`server.py`). قراءة تانية بتطلع بيانات من الموقع = سطر بـ `AUDIT_READ_ROUTES`. ❌ رابط تحميل مباشر بدون تأكيد.

17. **النشاط المباشر:** كرت الرئيسية = آخر 8 (`GET /admin/activity?limit=8`) + «عرض الكل» → قسم `#activity` (سطر بالـ registry) بصفحات من نفس الـ endpoint. ❌ قائمة بدون حد. الأعداد المعروضة عبر `twFormatNumber` (SYSTEMS_INDEX §59a).

18. **إجراءات الأدمن على المستخدم (task 5.3b2):** «تم» = التغيير صار فعلاً — `TwAdminShell.run` بيقبل `action.ok(body)` (2xx لحاله مش كفاية). **الرسالة** `POST /admin/message` = إشعار داخل الموقع نوع `admin_message` عبر `create_notification` (النص بيتخزّن متل ما انكتب — كل عرض بيعمله escape: `textContent` بصفحة الإشعارات، `esc` بالإيميل) + إيميل `admin_message` (notification) من نفس الـ hook → تفضيل المستخدم + الحدود. الرد `{ok:true, data:{notification_id}}`؛ إشعار ما انعمل → 500 `not_delivered` · مستخدم مش موجود → 404 · نص فاضي / أطول من 2000 → 422. `message.send` بـ `admin-view.js` بيفحص `data.notification_id`. **تغيير نوع الحساب** `PUT /admin/user/{id}/type` = `auth.set_user_type` (نفس الـ statement بيزيد `session_version`) + `_end_user_sessions` → المستخدم بيطلع من كل أجهزته وبيدخل على النوع الجديد (`auth-identity.md` → Session Version).
   - ❌ «تم» لإجراء ما انفحصت نتيجته · ❌ رسالة أدمن بالـ log بس · ❌ تغيير `user_type` بدون `session_version`.

19. **الوظائف (task 5.3j — SYSTEMS_INDEX §25e):** القائمة من `GET /admin/jobs` بس — كل الحالات (نشطة · موقوفة · مغلقة · منتهية · مؤرشفة)، الحالة جاية من السيرفر (`job_eff_status_sql` = توأم `_eff_status`) — ❌ حساب الحالة بالصفحة · ❌ الفيد العام كقائمة أدمن. تبويبات بعدد كل حالة + بحث (عنوان / شركة) + صفحات بالسيرفر + شارة لون لكل حالة (tokens). الحذف النهائي = `run('job.delete')` بالكلمة «حذف» ورسالة فيها عدد المتقدمين؛ السيرفر بيشيل مراحل التوظيف بنفس الـ transaction. أي فلترة «نشطة» بالسيرفر = `job_active_sql` — ❌ `status='active'` لحاله.
   - **المرحلة 2:** إجراءات كل صف من `jobActions(j)` (حسب `status` و `effective_status` من السيرفر): إخفاء (سبب إلزامي بنافذة) / إرجاع · إعادة تفعيل (مغلقة / منتهية) · تمديد (نشطة / موقوفة) · حذف — كلها `TwAdminShell.run` بتأكيد، و«تم» بس على `{ok: true}`. المدد من `durations` بالرد (`_ALLOWED_DURATIONS`) — ❌ مدد مكتوبة بالصفحة. كل إجراء بيوصل للشركة إشعار (السيرفر).
   - **المرحلة 3:** إيقاف / استئناف / إغلاق (سبب إلزامي) = `POST /admin/jobs/{id}/status` → نفس `set_job_status` تبع الشركة — ❌ كود حالة تاني للأدمن · إلغاء الأرشفة على الصفوف المؤرشفة. إعادة فتح المغلقة / المنتهية = الأدمن بس («إعادة تفعيل» → `_reopen_job`) — ❌ مسار شركة بيعيد فتح وظيفة (قرار صاحب المشروع 5.3j4).
20. **نافذة جمع قيمة وحدة:** `TwAdminShell.formDialog({titleKey, labelKey, kind: text | password | textarea | select, options?, value?, hintKey?, sendKey, onSend, danger?})` — زرّها بينادي `onSend(value)` (عادةً `run` وتأكيده فوقها). ❌ نافذة جمع قيمة خاصة بصفحة أدمن (كانت بـ `admin-view.js` — 5.3j).
